## 2.2. Нефункциональные требования

| ID | Требование | Как обеспечено |
|---|---|---|
| NFR-1 | Адаптивный и понятный интерфейс | Своя CSS-вёрстка mobile-first, бургер-меню < 860 px, тёмная тема по настройке ОС |
| NFR-2 | Хеширование паролей | PBKDF2-SHA256 с солью (стандарт Django), проверка сложности пароля |
| NFR-3 | Защита от SQL-инъекций | Только ORM Django с параметризованными запросами, сырого SQL нет; есть тест со спецсимволами |
| NFR-4 | Валидация вводимых данных | Серверная валидация во всех формах + ограничения CHECK и UNIQUE в БД + проверка в браузере для фото |
| NFR-5 | Время отклика ≤ 2–3 с | Индексы по статусу и дате, `select_related`, пагинация; замер — в [тестировании](05-testing.md) |
| NFR-6 | Разграничение доступа | Декораторы ролей, проверка владельца заявки, чужая заявка отдаёт 404 |
| NFR-7 | Защита от CSRF и XSS | CSRF-токены во всех формах, автоэкранирование шаблонов, изменения только через POST |
| NFR-8 | Конфиденциальность фото | Фото не раздаются из `/media/`, а отдаются через view с проверкой прав |
