# 7. Техническое описание программы

## 7.1. Общие сведения

| Параметр | Значение |
|---|---|
| Наименование | Веб-приложение «Ремонтная мастерская» (ФиксМастер) |
| Назначение | Приём заявок на ремонт техники, отслеживание статуса, учёт запчастей, аналитика |
| Язык | Python 3.13 (совместим с 3.12–3.14) |
| Фреймворк | Django 6.0 |
| СУБД | PostgreSQL 17 (рабочая), SQLite 3 (разработка и тесты) |
| Сервер приложений | Gunicorn 26, статика — WhiteNoise 6 |
| Клиентская часть | HTML5, CSS3 (без фреймворков), JavaScript ES2020, Chart.js 4.4 |
| Объём исходного кода | ≈ 1 900 строк Python, ≈ 740 строк тестов, ≈ 1 050 строк шаблонов, CSS и JS |
| Репозиторий | https://github.com/HackDanel/repair-shop (приватный) |

## 7.2. Модули

| Модуль (`apps/…`) | Ответственность | Основные файлы |
|---|---|---|
| `accounts` | Пользователь с ролью, регистрация, вход, профиль, проверка ролей | `models.py` (User), `forms.py`, `permissions.py`, `views.py` |
| `catalog` | Типы устройств, услуги, публичный каталог | `models.py` (DeviceType, Service), `views.py` |
| `repairs` | Заявки, история статусов, комментарии, фото, запчасти в ремонте | `models.py`, `services.py`, `forms.py`, `views.py`, `management/commands/seed_demo.py` |
| `inventory` | Склад: запчасти, движения, приход, инвентаризация | `models.py` (Part, StockMovement), `services.py`, `views.py` |
| `dashboard` | Панель администратора, статистика | `views.py`, `stats.py`, `forms.py` |

Зависимости между модулями: `repairs` использует `accounts`, `catalog` и `inventory`; `dashboard` читает
данные всех модулей; `catalog` и `inventory` от `repairs` не зависят.

## 7.3. Модели данных

| Модель | Таблица | Ключевые поля и правила |
|---|---|---|
| `User` | `accounts_user` | `role` ∈ {client, master, admin}; `email` уникален; телефон 10–15 цифр; свойства `is_client`, `is_master`, `is_admin_role` (суперпользователь — тоже администратор) |
| `DeviceType` | `catalog_devicetype` | уникальное название |
| `Service` | `catalog_service` | цена «от» ≥ 0, срок ≥ 1 дня, уникальна в пределах типа устройства, флаг показа в каталоге |
| `RepairRequest` | `repairs_repairrequest` | статус из 5 значений, `tracking_code` (UUID4) для публичной ссылки, стоимость работ ≥ 0, `issued_at` заполняется только в статусе «Выдана»; вычисляемые `parts_cost`, `total_cost`, `status_step` |
| `StatusChange` | `repairs_statuschange` | старый и новый статус, автор, время |
| `Comment` | `repairs_comment` | текст до 2000 символов, `is_internal` — скрыт от клиента |
| `Photo` | `repairs_photo` | файл в `media/requests/<id заявки>/<uuid>.<ext>` |
| `PartUsage` | `repairs_partusage` | количество ≥ 1, цена за штуку копируется из карточки в момент списания |
| `Part` | `inventory_part` | уникальный артикул (хранится в верхнем регистре), остаток ≥ 0, минимальный остаток, связь M:N с типами устройств |
| `StockMovement` | `inventory_stockmovement` | тип (приход, списание, возврат, корректировка), `delta` ≠ 0, ссылка на заявку |

Подробная схема — в [разделе 4](04-database.md).

## 7.4. Бизнес-логика (`services.py`)

Все операции, которые меняют несколько таблиц, выполняются в транзакции `transaction.atomic()`.

| Функция | Что делает | Проверки |
|---|---|---|
| `repairs.services.create_request` | создаёт заявку, первую запись истории и фото | — |
| `change_status` | меняет статус, пишет историю, ставит или сбрасывает `issued_at` | мастер — только своя заявка и только по схеме переходов; выдача только с назначенным мастером |
| `assign_master` | назначает или снимает мастера | только администратор; назначаемый — с ролью «Мастер» |
| `add_comment` | добавляет комментарий | доступ к заявке; клиент не может создать внутренний |
| `use_part` | списывает запчасть: уменьшает остаток, пишет движение и строку `PartUsage` | доступ; заявка не выдана; количество ≥ 1 и не больше остатка; строка запчасти блокируется `SELECT … FOR UPDATE` |
| `return_part` | отменяет списание и возвращает запчасть на склад | те же |
| `set_labor_cost` | сохраняет стоимость работ | доступ; заявка не выдана |
| `inventory.services.receive` | приход на склад | количество ≥ 1 |
| `inventory.services.adjust` | инвентаризация: выставляет фактический остаток, пишет разницу | остаток ≥ 0; нулевая разница не пишется |

## 7.5. Разграничение доступа

- `apps/accounts/permissions.py` — декораторы `client_required`, `staff_required`, `admin_required`. Без
  входа выполняется перенаправление на страницу логина, при чужой роли возвращается 403.
- Доступ к конкретной заявке проверяют `can_view` и `can_work_on` в `repairs/services.py`. Если заявка чужая,
  возвращается 404, чтобы не раскрывать, что заявка с таким номером существует.
- Фото раздаются только через `repairs:photo` с той же проверкой. Прямого публичного `/media/` нет.
- Публичная страница `/requests/track/<uuid>/` показывает только номер, устройство и этап.

## 7.6. Статистика (`dashboard/stats.py`)

`collect(months=12)` возвращает словарь `{kpi, charts}`. Его рендерит страница `/manage/stats/`, он же
доступен в JSON по адресу `/manage/stats.json`.

| Показатель | Как считается |
|---|---|
| Заявки по месяцам | `TruncMonth(created_at)`, `Count` |
| Доход по месяцам | сумма `labor_cost` + сумма `quantity × unit_price` по заявкам, выданным в этом месяце |
| Популярные неисправности | 8 самых частых услуг в заявках, «без услуги» — отдельная строка |
| Загрузка мастеров | незакрытые заявки и выданные за 30 дней на каждого активного мастера |
| Средний срок ремонта | среднее `issued_at − created_at` по выданным |

## 7.7. Настройки и переменные окружения

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `SECRET_KEY` | небезопасный dev-ключ | ключ подписи сессий и CSRF; на сервере генерируется случайно |
| `DEBUG` | `true` | режим отладки; на сервере `false` |
| `ALLOWED_HOSTS` | `localhost,127.0.0.1` | разрешённые домены |
| `CSRF_TRUSTED_ORIGINS` | — | origin для проверки CSRF за HTTPS-прокси |
| `SECURE_COOKIES` | `true` при `DEBUG=false` | cookie сессии и CSRF только по HTTPS |
| `DB_NAME`, `DB_USER`, `DB_PASSWORD`, `DB_HOST`, `DB_PORT` | — | PostgreSQL; без `DB_NAME` — SQLite |
| `MEDIA_ROOT` | `./media` | каталог загруженных фото |
| `TIME_ZONE` | `Asia/Novosibirsk` | часовой пояс отображения дат |

Константы в `config/settings.py`: `MAX_PHOTOS_PER_REQUEST = 5`, `MAX_PHOTO_SIZE = 5 МБ`, минимальная длина
пароля 8 символов.

## 7.8. Команды управления

| Команда | Назначение |
|---|---|
| `python manage.py migrate` | создать или обновить схему БД |
| `python manage.py seed_demo [--password P] [--requests N] [--seed S]` | заполнить пустую базу демо-данными |
| `python manage.py createsuperuser` | создать администратора (суперпользователь считается ролью «Администратор») |
| `python manage.py test` | запустить автотесты |
| `python manage.py collectstatic` | собрать статику (выполняется при сборке Docker-образа) |

## 7.9. Как расширять

- **Новый статус.** Добавить значение в `Status` и переходы в `TRANSITIONS` (`repairs/models.py`), стиль
  `.badge--<значение>` в `static/css/app.css`, затем создать миграцию.
- **Уведомления по e-mail.** Вызывать отправку в `services.change_status` после записи истории, настроить
  `EMAIL_*` в `settings.py`.
- **PDF-квитанция с QR-кодом.** Новый view в `repairs`, QR ведёт на `repairs:track` с `tracking_code`.
- **Kanban-доска.** Страница в `dashboard` с колонками по `Status`; перетаскивание отправляет POST на
  существующий `repairs:change_status`, так что правила переходов и права применяются автоматически.
