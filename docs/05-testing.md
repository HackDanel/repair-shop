# 5. Тестирование

## 5.1. Автоматические тесты

Тесты написаны на встроенном `django.test` и лежат в `apps/*/tests/`. Запуск:

```sh
python manage.py test                     # на SQLite
DB_NAME=repair DB_USER=repair DB_PASSWORD=repair DB_HOST=127.0.0.1 DB_PORT=5434 \
  python manage.py test                   # на PostgreSQL из docker compose
```

Результат на 21.10.2026: **76 тестов, все проходят** и на SQLite, и на PostgreSQL 17.

| Модуль | Файл | Что проверяется |
|---|---|---|
| Учётные записи | `accounts/tests/test_accounts.py` | регистрация, хеш пароля, нельзя зарегистрироваться админом, уникальный e-mail без учёта регистра, слабые пароли, границы телефона, обязательные поля, редирект по роли, заблокированный пользователь, выход только через POST |
| Каталог | `catalog/tests/test_catalog.py` | группировка, поиск, фильтр, некорректный параметр, пустой результат |
| Заявки | `repairs/tests/test_requests.py` | создание, фото (0, 2, 5, 6 штук, слишком большой файл, «не картинка»), границы длины описания, услуга от другого устройства, предзаполнение из каталога, доступ по ролям, защита фото, внутренние комментарии, публичная страница без персональных данных |
| Процесс ремонта | `repairs/tests/test_workflow.py` | полный путь статусов, запрет пропуска шагов, права админа, выдача без мастера, чужой мастер, списание и возврат запчастей, нехватка на складе, фиксация цены, блокировка выданной заявки, границы стоимости работ |
| Демо-данные | `repairs/tests/test_seed.py` | согласованность дат и статусов, повторный запуск запрещён |
| Склад | `inventory/tests/test_inventory.py` | приход, инвентаризация, флаг «мало», права мастера и клиента, нормализация и уникальность артикула, отрицательная цена, остаток не меняется через форму |
| Панель администратора | `dashboard/tests/test_dashboard.py` | доступ только админу, сотрудники, нельзя заблокировать себя, услуги (границы цены и срока), фильтры заявок, поиск со спецсимволами SQL, расчёт статистики |

## 5.3. Время отклика (NFR-5)

Замер 21.10.2026: приложение в Docker (Gunicorn, 3 worker), PostgreSQL 17, демо-набор из 120 заявок, по 20
запросов на страницу с ноутбука, на котором запущен Docker.

| Страница | Медиана | Максимум |
|---|---|---|
| `/` каталог | 13 мс | 38 мс |
| `/manage/` все заявки | 21 мс | 27 мс |
| `/manage/stats/` статистика | 26 мс | 32 мс |
| `/stock/movements/` журнал склада | 25 мс | 39 мс |
| `/requests/<id>/` карточка заявки | 24 мс | 35 мс |

Требование «не более 2–3 секунд» выполняется с большим запасом. Нагрузочное тестирование с сотнями
одновременных пользователей не проводилось.

Найденные и исправленные дефекты:

| № | Дефект | Исправление |
|---|---|---|
| 1 | Пустая отправка формы (POST без полей) показывала форму без ошибок | Форма связывается с данными по методу запроса, а не по их наличию |
| 2 | На ширине телефона карточка заявки выходила за край экрана | `minmax(0, 1fr)` в CSS-сетках |
| 3 | У администратора в списке статусов по умолчанию стоял «Принята» вместо текущего | Начальное значение — текущий статус заявки |
| 4 | Список клиентов на странице мог меняться местами между запросами | Явная сортировка при агрегации |
